# Urban Intelligence Platform — landing

Second landing of the Pixels to Metro Policy pair. The first longread
(`../Pixels_to_Metro_Policy_landing`) ends with the "Open the Urban Intelligence
Platform" button; this page is its target. Same visual system (Archivo + IBM Plex,
dark HUD theme, d3), built as one self-contained folder — no CDN dependencies.

## Pipeline

The hero shows the algorithm after `labeling/qgis_project/urban platform
scheme.pdf` as 10 blocks: 8 tools (segmentation → matching → social sensing →
ranking → priorities → participation → kit → design/approval), the output block
(intervention program) and the assessment block that closes the loop. Data
sources (THEOS-2 imagery, cadastre/masterplans, the daily urban datalake) are not
separate nodes — each tool's description and rollup names its own inputs. Every
block is a separate JS module in `web/js/blocks/` (one file per block) with a
canvas micro-animation that starts on hover; hovering also opens a floating panel
with the block's text and its own video.

## Sections (one per tool block)

1. **Satellite segmentation tool** — process strip; interactive map of segmented
   roofs (3 sites, ~9k buildings from `slum_roofs_red_v8`) with accepted blob hulls
   (blobcompare A/B/C); hover roofs and hulls for evidence.
2. **Match to regular properties** — BMA plan zones (605) under the roofs; live
   morphology sliders (roof area / neighbour count) flag true irregular blocks;
   zone hit-testing via an offscreen id raster.
3. **Social sensing tool** — datalake process, 6 domain layers over 1,993
   communities (from `social.html`'s embedded dataset), then the **ranked
   irregular neighborhoods** sub-block: signal-weighted ranking, top-15 table,
   solo / bivariate (score × event volume) map.
4. **Priorities & selection** — district aggregation of community scores via
   raster point-in-polygon; P1–P4 priority classes.
5. **Selection of participation techniques** — 35 cards in 6 class carousels,
   class-coloured, photographic class backgrounds (Wikimedia Commons — see
   `web/img/part/SOURCES.md`), KIT/TH tags, failure-modes note.
6. **Selection of a kit of urban governance** — scroll-snap kit picker (centered
   kit = selected, detail panel below), 6 flip cards (front: precedent + image;
   back: actions + participatory techniques), interactive bezier scheme wiring
   kits to participation classes (solid = floor, dashed = ceiling).
7. **Design & approval** — the full walkthrough video (114 MB local) and the
   illustrative intervention strategy on the #1 ranked area: fire lane /
   re-blocked plots / common-use / market-zone layers, four flip cards connected
   to map locations by dashed lines.

Each section has a "Full description & data sources" rollup (details element).

## Files

- `web/index.html` — the page
- `web/css/uip.css`, `web/css/fonts.css` + `web/fonts/` — style (shared tokens)
- `web/js/uip-data.js` — pipeline, texts, cards, kits (content layer)
- `web/js/blocks/*.js` — 13 pipeline-block animation modules
- `web/js/uip-main.js` — assembly: maps, ranking, carousels, bezier, scroll-snap
- `web/data/uip-*.json` — trimmed layers, generated by `prep_data.py`
- `web/media/` — fire/flood clips + disaster clips + full walkthrough
- `web/img/kits/`, `web/img/part/` — kit imagery (own outputs) + class photos

## Build / data refresh

```
python prep_data.py
```

Re-reads repo sources (`labeling/qgis_project`, `05_scratch/deploy_site/data`,
`social.html`) and rewrites `web/data/`. Bump `DATAV` in `uip-main.js` if you
serve with caching.

## Serve

From the repo root (so the footer links to the interactive tabs resolve):

```
python -m http.server 8765
# http://127.0.0.1:8765/kla/final_html/Urban_Intelligence_Platform_landing/web/
```

Note: maps size themselves on load, on window resize, on a poll, and on any
scroll/pointer event — a workaround for embedded webviews that lay out at
innerWidth 0 and never dispatch resize.
